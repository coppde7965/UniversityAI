# UniversityAI 專題文件

本專案交付物為 **Moodle 5.2 外掛套組**（見 SRS `D-07`、`D-09`）：`local_universityai`（核心）、`block_universityai`（課程頁面聊天區塊）、`aiprovider_claude`（Claude 供應商）。產品程式碼為 PHP，全部執行於 Moodle 站台之內，分層採 MVVM 並以 Moodle Output API 實現（`D-08`）。

開發與展示環境一律容器化（`D-04`），操作一律經由 Makefile（§2.5）。**主機端只需安裝 Docker 與 GNU Make**，不安裝 PHP、Composer、Node 或 Python。

> Moodle 自 5.1 起把網站根目錄移入 `public/`，外掛安裝路徑為 `public/local/universityai`、`public/blocks/universityai`、`public/ai/provider/claude`。網路上多數 Docker 教學仍是舊的扁平結構，照抄會得到 404。

## 三份文件的關係

SRS 定義**要做什麼**與**怎樣算做完**，是另外兩份文件的上游。

架構文件定義**怎麼做**，其中每個設計決定應能追溯到 SRS 中的需求編號或 §2.2 的決策紀錄；若架構文件出現 SRS 沒有的功能，代表 SRS 漏寫，回頭補 SRS 而不是在架構文件中新增需求。

BDD 規範定義**怎麼驗證**。它把 SRS §4 與 §6 的每一條驗收條件分派到四個驗證層級（PHPUnit／Behat／評測腳本／人工），並以需求編號作為 tag 建立雙向追溯。**它不重複 SRS 的驗收條件**，只決定驗法。

```
SRS.md  ──要做什麼──▶  architecture.md  ──怎麼做──▶  外掛程式碼
   │                                                     ▲
   └────────怎樣算做完────▶  bdd-guide.md  ──驗證───────┘
                                  │
                                  └──▶ <各外掛>/tests/behat/*.feature
```

## architecture.md 的重點

除 §9 之外皆已完成（v0.9）。五個設計決定以 `A-01`~`A-05` 編號，索引在該文件 §11。其中影響最大的兩個：

- **`A-02`　課綱以整份 JSON 存放，不正規化成 weeks／events 子表**，唯一例外是「課綱事件 ↔ Moodle 事件」的對應抽成獨立表以支撐冪等性。關鍵理由是 XMLDB 根本沒有 JSON 型別，「存 JSON 但用 SQL 查裡面」這條路在 Moodle 的資料庫抽象層下不存在。
- **`A-05`　去識別化規則以資料共用，實作不共用**。SRS `NFR-SEC-06` 寫的「共用同一份實作」在 PHP 與 Python 之間無法照字面做到，改以共用規則檔加共用黃金樣本達成同樣目的。**此處與 SRS 措辭有落差，已在該文件標明**，SRS 下次修訂時應一併改。

**§9 AI 呼叫設計是空的**，且刻意如此：它依賴 SRS §8.4 第一‧五階段的三項實測，未做完前寫了也只是猜測。該章列出了完成後必須回答的七個問題。其餘章節不受阻擋——資料表、任務、權限、環境都不依賴 AI 怎麼實作，只依賴它會被呼叫且可能失敗。

`OI-05` 的刪除清單與執行順序也在該文件 §10 定案：**第一階段完成之後、第三階段開始之前**執行，且須先把 PDF 文字抽取邏輯抽進 `eval/`。

## bdd-guide.md 的重點

規範已完成（v1.0），撰寫測試前請整份讀過。若只記三件事：

1. **先查層級**。每條需求該用 PHPUnit、Behat、評測腳本還是人工驗，規範 §3 有完整對照表。L1 能驗的不要寫成 L2；L3 與 L4 不得單獨滿足「必要」需求。
2. **不得接觸真實外部服務**。Claude API、Google Calendar 一律替換，替換方式見規範 §9。
3. **忘記 `@javascript` 是浪費時間最多的錯誤**。症狀是「畫面明明有，測試找不到元素」。

`moodle-plugin-ci` 同時涵蓋程式碼檢查、gherkin lint、PHPUnit 與 Behat，也是 `NFR-MNT-04` 的驗收工具，優先確認它能在本機跑起來。

> 既有的 `tests/features/syllabi.feature` 與 `tests/step_definitions/` 屬 Python 專案，隨 `OI-05` 移除，不需遷移內容——但其中「英文關鍵字、繁體中文場景」的寫法已被規範沿用。

## 尚未決定的事項

SRS §10.2 僅剩 `OI-06`（課綱內容送出校外的合規性、API 費用歸屬），已決定延後至 MVP 之後處理，**不阻擋任何開發階段**。

之所以能安心延後，是因為 `NFR-EXT-03` 把供應商切換做成站台設定：日後若校方不允許內容送出校外，改用本地或校內模型只需在後台換一個供應商外掛。

但 v1.4 之後這個前提附帶兩個條件，都必須在 MVP 期間就成立，否則延後就變成埋雷：

1. 生成類功能走 Moodle AI 子系統，換供應商確實零改動；但**抽取類功能走的是外掛自訂介面**（`D-05`），換用未實作該介面的供應商時要靠通用實作接手，所以**那條通用實作必須隨第一版交付**，不能等日後再補。
2. `NFR-SEC-06` 的資料最小化與去識別化必須從第一版就實作，不能等日後再補過濾。
